# Code Standards

## General

- Follow the Single Responsibility Principle (SRP). Every module, service, component, and API endpoint must have one clear responsibility.
- Prefer composition over inheritance whenever possible.
- Write clean, readable, and self-documenting code.
- Keep business logic independent from AI logic, notification logic, and presentation logic.
- Avoid duplicate code by creating reusable services and shared utilities.
- Fix root causes instead of introducing temporary workarounds.
- Avoid hardcoded values; use configuration files or environment variables.
- Every Pull Request should implement one feature or one bug fix only.
- Follow Conventional Commits for commit messages.
- Every feature must support the platform's collaborative workflow (Administrator, Lawyer, Court Representative).

---

## TypeScript

- Enable strict mode throughout the project.
- Never use `any`; prefer explicit interfaces, types, or generics.
- Validate all external input using Zod.
- Prefer immutable objects whenever possible.
- Use enums or union types instead of magic strings.
- Export shared DTOs and interfaces from the shared package.
- Keep React components strongly typed.
- Avoid duplicated business models.

---

## Next.js

- Use the App Router architecture.
- Prefer Server Components by default.
- Use Client Components only when browser interactivity is required.
- Keep page components lightweight.
- Extract reusable UI into shared components.
- Never place business logic inside React components.
- Use feature-based folder organization.
- All user-facing text must support localization.

---

## FastAPI

- Keep API routes thin.
- Business logic belongs inside service classes.
- Validate every request using Pydantic models.
- Return standardized API response structures.
- Use dependency injection for authentication and database sessions.
- Separate routers, services, repositories, and schemas.
- Long-running operations must execute asynchronously.
- Real-time events must be handled using WebSockets.

---

## AI Services

- Never call an LLM directly from API routes.
- All AI interactions must pass through the AI orchestration layer.
- Every AI response must use Retrieval-Augmented Generation (RAG) whenever company documents are involved.
- Prompt templates must be version-controlled.
- AI prompts must remain independent from application logic.
- Every AI agent must have a single responsibility.
- Every AI-generated response must include references to the source documents.
- AI interactions should be logged for observability without exposing confidential information.
- AI must detect and respond in the user's selected language (Arabic or French).

---

## Real-Time Collaboration

- Case updates must be synchronized instantly across all authorized users.
- WebSocket events must be event-driven.
- Real-time events must be idempotent whenever possible.
- Every state change must update connected users immediately.
- Synchronization logic must remain independent from business logic.

---

## Notifications

- All notifications must be generated by the Notification Service.
- Notification logic must never be duplicated.
- A single business event may generate:
  - In-app notification
  - Email notification
  - WhatsApp notification
- Notifications must be persistent and recoverable.
- Notification delivery failures must be retried automatically.
- Scheduled reminders must execute through background workers.

---

## Internationalization (i18n)

- Never hardcode user-facing strings.
- Every text must use translation keys.
- Support both Arabic and French.
- Arabic pages must support Right-to-Left (RTL).
- Dates, numbers, and currencies must follow locale formatting.
- AI responses must preserve the selected language.

---

## Styling

- Use Tailwind CSS utility classes.
- Build reusable UI components with shadcn/ui.
- Never hardcode colors.
- Use design tokens defined in the UI context.
- Maintain consistent spacing and typography.
- Ensure responsive layouts.
- Follow accessibility (WCAG AA) guidelines.

---

## API Routes

- Validate every request before executing business logic.
- Authenticate every protected endpoint.
- Authorize every action using Role-Based Access Control (RBAC).
- Verify case ownership or assignment before exposing resources.
- Return consistent JSON responses.
- Use appropriate HTTP status codes.
- Never expose internal exceptions.
- Keep controllers free of business logic.

---

## Data and Storage

- Store business data inside PostgreSQL.
- Store document embeddings inside Qdrant.
- Store uploaded files inside MinIO.
- Store temporary cache and queues inside Redis.
- Never store large files inside PostgreSQL.
- Preserve version history for legal documents.
- Never permanently delete legal documents without authorization.
- Store passwords using Argon2 or bcrypt.
- Never commit secrets or credentials to the repository.

---

## Security

- Apply the Principle of Least Privilege.
- Enforce Role-Based Access Control (RBAC).
- Lawyers may only access assigned cases.
- Court representatives may only access authorized cases.
- Administrators have platform management permissions.
- Validate and sanitize all user input.
- Enforce HTTPS in production.
- Protect against SQL Injection and Cross-Site Scripting (XSS).
- Limit upload size and supported file types.
- Store secrets only in environment variables.
- Audit every sensitive operation.

---

## Background Jobs

- OCR processing executes asynchronously.
- Embedding generation executes asynchronously.
- Document indexing executes asynchronously.
- AI report generation executes asynchronously.
- Notification delivery executes asynchronously.
- Scheduled reminders execute asynchronously.
- Background jobs should be idempotent whenever possible.
- Retry failed jobs using exponential backoff.

---

## Error Handling

- Fail gracefully with meaningful error messages.
- Log unexpected exceptions.
- Never expose stack traces in production.
- Return standardized error responses.
- Differentiate validation errors from server errors.

---

## Testing

- Write unit tests for business logic.
- Write integration tests for API endpoints.
- Test real-time synchronization.
- Test notification delivery.
- Test multilingual functionality.
- Test AI retrieval pipelines independently.
- Validate AI outputs using evaluation datasets.
- Run automated tests before every merge.
- Do not merge failing builds.

---

## File Organization

- `apps/web/` — Next.js frontend for administrators, lawyers, and court representatives.
- `apps/api/` — FastAPI backend application.
- `modules/cases/` — Case lifecycle management.
- `modules/documents/` — Document management and OCR.
- `modules/reports/` — Report generation and exports.
- `modules/notifications/` — Notification service (In-App, Email, WhatsApp).
- `modules/users/` — User management and RBAC.
- `modules/localization/` — Arabic, French, translations, and RTL support.
- `services/ai/` — AI agents, RAG pipeline, embeddings, prompts, and LLM integrations.
- `services/workers/` — Background jobs, OCR, indexing, reminders, and scheduled tasks.
- `packages/shared/` — Shared types, DTOs, validation schemas, utilities, and constants.
- `packages/ui/` — Shared UI components.
- `infrastructure/` — Docker, Nginx, monitoring, deployment, and CI/CD.
- `docs/` — Project documentation, architecture decisions (ADRs), specifications, and diagrams.
- `tests/` — Unit, integration, and end-to-end tests.

---

## Event-Driven Architecture

- Every important business action (case creation, lawyer assignment, document upload, court update, report generation, etc.) must emit a domain event.
- Other modules (Notifications, AI, Audit Logs, Timeline) should react to these events instead of being called directly.
- This keeps the platform loosely coupled and makes it easier to add future integrations without modifying existing business logic.
