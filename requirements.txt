# --- OCR (document text extraction) ---
# pytesseract and pdf2image are thin wrappers around two *system* binaries that
# are NOT installed by pip and must be present on the host (or in the API image):
#   * Tesseract OCR  — the recogniser. Point TESSERACT_CMD at it if it is not on
#     PATH, which it is not on a default Windows install.
#     Debian/Ubuntu: apt-get install tesseract-ocr tesseract-ocr-fra tesseract-ocr-ara
#     Windows:       https://github.com/UB-Mannheim/tesseract/wiki
#   * Poppler        — pdftoppm/pdfinfo, which render PDF pages to images. Point
#     POPPLER_PATH at the directory holding them if it is not on PATH.
#     Debian/Ubuntu: apt-get install poppler-utils
# Their absence is handled rather than fatal: extraction records a `failed` run
# with error_code `engine_failure`, the uploaded document is untouched, and the
# run stays retryable once the binary is installed.
pytesseract==0.3.13
pdf2image==1.17.0
pillow==12.1.0

# --- Document indexing (chunking + embeddings) ---
# The second stage of the AI pipeline: it turns the text OCR extracted into
# vectors in Qdrant. Both libraries are wrapped behind protocols
# (`services/chunking.py`, `services/embedding.py`), so neither is imported
# anywhere else in the platform.
#   * langchain-text-splitters — recursive character splitting, per the spec's
#     "use mature libraries […] do not implement custom chunking algorithms".
#     Small and pure Python; it pulls langchain-core but no model and no network.
#   * sentence-transformers    — the embedding runtime for BAAI/bge-m3, the model
#     `ai-architecture.md` names. **It pulls torch (~2.5 GB installed) and
#     downloads the model itself (~2.3 GB) on first use**, cached under
#     HF_HOME / ~/.cache/huggingface. Neither is fetched at import time or at
#     startup: the model loads lazily on the first indexing run, so a deployment
#     without it still starts, serves every other feature, and reports
#     `embedding_available: false` on GET /indexing/metrics — the same posture a
#     missing Tesseract takes for OCR.
langchain-text-splitters==1.1.2
sentence-transformers==5.6.1

# --- RAG pipeline (orchestration, prompts, LLM provider) ---
# The fourth stage of the AI pipeline: it retrieves through the semantic search
# service, assembles a versioned prompt, invokes a language model once, and
# returns a grounded answer with citations. Each library is wrapped behind a
# protocol (`services/rag_graph.py`, `services/prompts.py`, `services/llm.py`),
# so none is imported anywhere else in the platform.
#   * langgraph   — the orchestrator context/ai-architecture.md names. Small and
#     pure Python; it pulls langgraph-checkpoint/-prebuilt/-sdk and no model.
#     NOTE: langgraph-sdk pins `websockets<16`, which downgrades the package from
#     17.x. Uvicorn's WebSocket support works on both, so Real-Time
#     Synchronization is unaffected — but if that feature ever needs a 16+ API,
#     the resolution is to run LangGraph without the SDK extra.
#   * jinja2      — prompt templates, which live in `apps/api/prompts/` as
#     versioned `.j2` files rather than as strings in Python, so a prompt change
#     is reviewable as a diff. Already present transitively; declared here
#     because the platform now imports it directly.
#   * google-genai — the Gemini SDK, behind the `LLMProvider` protocol.
#     **No key is needed to install, run, or test.** A deployment without
#     LLM_API_KEY still starts, serves every other feature, and reports
#     `llm_available: false` on GET /rag/metrics — the same posture a missing
#     Tesseract takes for OCR.
#
# `litellm` is deliberately NOT listed. It is the second, optional provider
# backend (`LiteLLMProvider`), imported lazily, for deployments that want
# OpenAI, Ollama, Groq, or Anthropic instead of Gemini. It pulls a large
# dependency tree a Gemini deployment does not need, so install it explicitly:
#     pip install litellm
langgraph==1.2.10
jinja2==3.1.6
google-genai==2.17.0

# --- AI report generation (export rendering) ---
# The sixth stage of the AI pipeline produces a structured, cited legal report by
# running the RAG pipeline once per section. It adds **no AI dependency at all** —
# it retrieves nothing, builds no prompt, and calls no model of its own — so
# everything here is about turning a finished report into a file.
#   * reportlab — PDF rendering, behind the `ReportRenderer` protocol
#     (`services/report_export.py`), so it is imported nowhere else. Chosen over
#     WeasyPrint and wkhtmltopdf because those need system libraries or a headless
#     browser in the image, and this platform already carries two binaries pip
#     cannot install (Tesseract and Poppler); a third would be a third thing to
#     explain in a deployment guide. Its absence is handled rather than fatal:
#     PDF export answers 503 naming Markdown, `GET /reports/metrics` omits `pdf`
#     from `available_formats`, and Markdown export — which needs no library at
#     all — is unaffected.
#   * arabic-reshaper + python-bidi — Arabic shaping and bidirectional reordering.
#     **Required, not optional**, and the distinction from `litellm` is the point:
#     `litellm` is an alternative to something that already works, while these are
#     the difference between correct Arabic and mangled Arabic. ReportLab draws
#     glyphs in the order it is given them and performs no joining, so without
#     these an Arabic report exports as disconnected letters in reverse order.
#     `project-overview.md` names Arabic as one of the platform's two languages,
#     so that is not an edge case — it is half the intended users. Both are small
#     and pure Python.
#
# **PDF export of Arabic also needs a font**, because ReportLab's built-in Type 1
# fonts cover Latin script only. It is NOT a pip dependency and NOT a manual step
# in the common case: `services/report_export.py` searches a list of well-known
# paths (Noto Naskh, Amiri, FreeSerif, and the macOS/Windows system faces) and
# verifies each against the font's own character map before using it — so a
# Debian image with `fonts-noto-core` and a Windows host both work unconfigured.
# `REPORT_PDF_FONT_PATH` overrides the search. For a container image:
#     apt-get install -y fonts-noto-core     # or fonts-hosny-amiri
reportlab==4.4.4
arabic-reshaper==3.0.1
python-bidi==0.6.11
